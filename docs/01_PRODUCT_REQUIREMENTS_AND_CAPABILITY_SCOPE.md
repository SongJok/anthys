## 1. 产品定义

**anthys 是运行在钉钉中的企业 AI 助理及受授权的群事务执行系统。**

入口是企业内部应用机器人、单聊、群聊、互动卡片及应用内管理页；执行中枢是 `glm-5.3-flash` 的原生思考与工具调用循环；公司已有 MCP 提供线上代码与日志；DWS 与钉钉 OpenAPI 提供经过授权的办公能力；PostgreSQL 保存业务状态、记忆、任务、审计与队列；采用 Docker 部署。

它不是只有问答能力的群 Webhook，也不是能无限制操作企业资源的“超级管理员”。目标是：员工只需说明目标，系统自主补齐可检索信息、选择工具、执行、验证和交付，遇到真正的权限缺失、关键歧义或高风险操作才中断寻求人类处理。

### 1.1 三个必须分开的概念

1. **模型能力完整**：保留厂商支持的思考、工具调用、流式、多模态输入与结构化输出，不把模型退化成意图分类器。模型卡确认 `glm-5.3-flash` 支持原生思考与 Function Calling，但这不自动赋予外部系统权限。[S01]
2. **任务自主完整**：目标管理、工具发现、持续执行、暂停恢复、定时触发、核验和通知是本项目必须实现的运行时能力。
3. **企业授权受控**：应用权限、用户委托、资源 ACL、本系统策略及输出受众授权共同决定是否可执行。任何一层拒绝都不能由模型覆盖。

“原生思维链”在本项目中指使用模型真实的协议能力，不要求模型输出私密内部推理给用户，不强制编造固定的“思考—反思—思考”长文本。前台展示动作、依据、状态和简短理由；模型返回的内部推理字段仅按厂商要求在受保护的运行时协议中处理，详见文档 02。

### 1.2 成功的典型体验

> 员工：“帮我查下今天支付失败为什么多，结合线上日志和代码给个结论，每半小时看一次，恢复了告诉我。”

系统自行确定时间范围和所涉服务，使用有权访问的 MCP 搜索日志与版本化代码，区分事实和假设，交付可点击的证据；在用户有监控权限时建立可停止的条件任务，输出明确任务编号、频率、有效期和通知目标。不能查询生产资源时说明实际缺少的接入或权限，不生成假日志。

> 群主：“负责这个发布群，收集阻塞项，下午五点汇总，催一下逾期负责人。”

系统先确定群授权、消息来源覆盖度、成员范围、时区、催办上限和有效期。只在获授权的群中工作；持续维护事务清单；按授权发送摘要和有限催办。没有非 @ 消息读取能力时，使用 @/卡片提交的事务，不声称监听了全部讨论。

## 2. 已核实的外部边界

### 2.1 钉钉机器人不是万能钉钉客户端

标准应用机器人接收通道支持人与机器人单聊，以及群中 @ 机器人的消息。不能由此推断可以读取任意历史消息、全部非 @ 消息或其他人的私聊。[S04]

DWS 是另一条带身份授权的办公能力通道。其官方资料包含会话历史/搜索和群操作能力，但实际命令、身份、资源范围、租户资格及运行环境必须分别核验。**标准机器人通道受限，不等于所有 DWS 历史读取都不可实现；DWS 存在相关能力，也不等于机器人自动拥有它。**[S09][S10][S11]

应用机器人是默认发送身份。使用 DWS 用户身份代发必须显式授权，并在预览中说明“以谁的身份发送”；禁止悄悄从机器人发送切换为员工身份。

### 2.2 开发者后台权限只是一个授权入口

后台申请 OpenAPI 权限点后，仍可能需要应用发布、可用范围配置、个人委托、CLI 开通和目标资源权限。官方权限排错说明同时涉及应用权限和授权类型，不能用“AppKey/AppSecret 已填”表示全部接入成功。[S07][S09]

本系统不得尝试自动点击管理员控制台批准自己、借用管理员登录态扩大权限、使用一个人的 DWS 登录身份读取所有员工资源。

### 2.3 dots 对标采用能力清单，不使用模糊的“已等效”

参考其持续个人上下文、长程任务和跨工具工作方向，而不是宣称复刻闭源产品的实现、产品权限或服务覆盖。[S17] 本项目用下表定义实际交付范围。

| 参考方向 | anthys 的验收定义 | 明确不作承诺 |
|---|---|---|
| 个性化助理 | 企业/群/个人三级人设，持久偏好，可查看修改和删除 | 模型永远不会误解用户 |
| 连续工作 | 持久任务、检查点、离线恢复、定时与条件监控 | 无期限、无成本、无边界自主运行 |
| 主动帮助 | 对已授权的目标做变化发现，聚合后通知 | 默认监听所有员工全部活动 |
| 跨工具执行 | 钉钉、DWS、公司 MCP、数据模板、搜索、文件 | 未接入系统自动可用 |
| 工作成果 | 报告、表格、待办、会议安排、指导计划 | 每次输出都无需人类核验 |
| 工作环境 | 隔离的 Node/TypeScript 分析沙箱，受控浏览能力 | 接管员工电脑、任意桌面点击 |
| 多模态 | 经实际 API/通道验证的图片、文件输入 | 自动提供音频通话、图片生成或视频生成 |

## 3. 交付范围与发布剖面

为了避免将外部尚未授权的能力伪装成已交付功能，建立三种发布剖面。它们是验收集合，不是三个互不兼容的产品。

### 3.1 BASE：基础可用剖面

必须具备：真实钉钉单聊与群 @；卡片或受控文本降级；模型工具闭环；用户身份；人设和个人/群记忆；本地任务；定时器；群事务清单；公司代码/日志 MCP；认证的数据模板；搜索接入；文件成果；权限中心；审计；Docker；完整自动化测试。

BASE 发布时每一个已开启的外部适配器必须通过真实联调。没有真实 MCP 或数据模板接入时只能标记为 `DEMO_ONLY` 或受限试点，不能宣传线上业务查询/统计已可用。

### 3.2 ENTERPRISE_DWS：本次最终目标剖面

在 BASE 之上，必须完成 DWS 真实授权、按用户隔离、能力发现和许可内读写，以及联系人、待办、日历、文档/文件、AI 表格、群资料/事务的端到端验证。企业选定的 DWS 历史/搜索能力通过认证后，才能开启群增强感知。

最终版本必须实现所有 DWS 适配器与前端状态，即使部分租户没有开通某一产品。受租户限制的能力应明确 `BLOCKED_EXTERNAL`，不能算作 `PASS`，也不能以“留一个空接口”代替实现。

### 3.3 扩展能力

审批提交/查询、工作报告、会议纪要、考勤、公告、DING、邮件、知识库、白板等按实际 OpenAPI/DWS 能力注册。对企业正式勾选为必需的扩展，自动加入发布门禁；其余可以禁用，但不能显示虚假成功。

危险能力（解散群、批量移除成员、公开分享文件、人事权限变更、审批决策、生产写操作）不作为默认自主能力。默认拒绝；只有单独评审和逐次授权的已认证连接器才可开启。其中生产写操作不在本次既有只读 MCP 假设内。

## 4. 用户、角色与身份

| 角色 | 主要权限 | 不能默认获得 |
|---|---|---|
| 企业应用管理员 | 配置应用、可见范围、连接器、租户策略、预算 | 任意员工私聊正文、用户个人 DWS 授权 |
| 安全审计员 | 脱敏审计、策略版本、审批记录、访问调查 | 全量推理内容、任意业务数据导出 |
| 数据负责人 | 发布/下线统计模板、指标定义、数据资源授权 | 全员聊天记忆 |
| 群主/授权群管理员 | 设置本群助理职责、工作时间、群内事务规则 | 群成员私人记忆、其他群权限 |
| 普通员工 | 自己的问答、任务、授权资源、个人偏好与定时任务 | 因机器人连接了生产 MCP 就访问所有日志 |
| 受托服务身份 | 在指定群/资源/时间内执行已登记职责 | 自动冒用群主或离职员工身份 |

角色权限还要叠加部门、项目、数据分类、资源 ACL 和输出受众，不以 UI 菜单可见性代替后端鉴权。

同名人员必须通过目录信息解析为稳定身份；`corpId`、`userId`、`unionId`、`openDingTalkId` 分别保存，禁止互相当作等价字符串使用。外部群/跨企业成员默认不开放内部代码、日志和统计结果。

## 6. 单聊产品交互

### 6.1 首次使用

首次对话确认企业身份，返回一张助理说明卡：能做什么、当前已接入哪些能力、信息如何使用、如何设置人设/查看记忆/停止任务。只有需要个人资源时才发起个人授权；普通日常问答不应被全套 DWS 授权流程阻塞。

用户可问“你能做什么”“目前缺哪些权限”“谁能看见我们的对话”。回答来自实时能力状态和策略，不能从静态宣传文案生成。

### 6.2 对话与任务关联

每个任务有可见编号。后续“继续”“只看昨天”“发到项目群”必须解析到具体任务，并重新检查时间、资源和输出受众变化。多个可选任务存在时展示选择，而不是凭猜测把私人报告发到群。

“停止”优先被确定性控制层识别，不等模型下一轮自行决定。撤销正在执行的外部请求只能尽力取消，系统不得把“取消请求已收到”说成“外部副作用已经撤回”。

### 6.3 默认回答格式

简单日常问题自然回答，不机械塞入全部字段。业务/数据问题通常输出：结论、关键依据、统计口径或代码/日志位置、尚未确认项、已完成动作。长任务先回执，随后更新同一状态卡，避免逐 token 发新消息刷屏。

## 7. 人设与工作指导

人设字段：名字、角色定位、语气、输出长度、称呼习惯、专业职责、禁止冒充内容、默认输出模板、工作时间。示例内置“企业助理”“群事务秘书”“数据分析助理”“技术排障助理”，不是不同的权限主体。

优先级：安全与授权规则 > 企业政策 > 群工作合同（群会话）/个人偏好（单聊） > 当前用户指令 > 人设风格 > 检索内容。

用户可设置“回答直接一些”“提醒我先列验证步骤”。不能以“你的人设是总经理/超级管理员”扩权，不能对外伪称真实领导授意。

指导工作要交付可执行的检查清单、依赖与风险、验证方式；对于线上修改提供方案或变更草案，不因建议被认可就自动部署。涉及法律、人事、财务等高风险决策给出材料与流程，交由授权人员决定。

## 8. 群事务产品

### 8.1 群授权合同 GroupContract

必须由经过验证的群主/授权管理员创建，至少包含：群标识、责任范围、数据来源、可执行动作、禁止动作、工作时段、催办频率、允许 @ 的人员、升级对象、有效期、预算、负责服务身份、撤销方式。

“机器人已被拉进群”仅表示消息入口成立，不自动创建广泛委托。合同中不得批准读取群成员私人 DWS 会话。

### 8.2 三种群工作模式

| 模式 | 信息来源 | 可完成事项 |
|---|---|---|
| `MENTION_ONLY` | @机器人、单独提交的卡片、手动导入且授权的资料 | 问答、记录事项、分派、催办、指定范围汇总 |
| `AUTHORIZED_HISTORY` | 上述来源 + 已认证的 DWS 会话历史/搜索 | 指定时段摘要、遗漏事项候选、讨论关联、上下文补全 |
| `AUTHORIZED_EVENTS` | 租户实际支持并认证的合法事件源 | 近实时发现变化；并非所有企业默认具备 |

新群默认 `MENTION_ONLY`。增强模式必须展示群内告知，记录管理员授权、服务身份、来源时间窗及保留期。轮询历史不等于实时订阅；界面显示实际延迟。

### 8.3 事务状态机

`PROPOSED → OPEN → ASSIGNED → IN_PROGRESS → BLOCKED/WAITING_CONFIRMATION → RESOLVED → CLOSED`；允许 `CANCELLED`。

自然语言“已经好了”仅是一个完成声明。需要对应执行者确认或验证证据，才转为已解决；群合同允许自报完成的普通事项应标记验证方式为 `OWNER_REPORTED`，不能伪装成自动验证。

任务必有标题、原始消息/资料、负责人、截止时间或“未设置”、优先级、阻塞原因、状态更新时间、提醒规则、来源覆盖。模型猜出的负责人只能作为候选，不能未经授权指派。

### 8.4 催办与升级

默认每件事务每天主动催办不超过 2 次，每群工作时段内主动摘要不超过 6 条/小时；都是项目默认值，可由管理员调低。@全员默认禁用。重复状态合并，优先在私聊提醒有授权的责任人；跨通道发送须满足受众权限。

群管理员可自然语言或卡片“暂停群助理”“停止催办”“只做问答”。停用在下一次任何工具执行和发送前重新检查，不能等待原合同到期。

## 9. 定时任务和主动任务

支持一次性提醒、RRULE 周期、指定工作日/企业工作日历、固定间隔条件监控。存储 IANA 时区、原始自然语言、解析后绝对时间、重复规则、开始/结束、执行身份、通知目标、授权快照、错过执行策略。

“每个工作日 9 点发日报”必须区分周一到周五与法定调休工作日。默认只使用周一到周五并在确认中写清；法定工作日需配置版本化企业日历，不能靠模型记忆判断。

对只缺少可安全默认值的创建请求，展示已经采用的时区与时间；对收件人、日期、权限存在实质歧义的请求，先澄清。显式要求创建单次私人提醒即视为对该低风险动作的同意；不能所有提醒都多问一轮。

周期任务给出未来 5 次执行预览。夏令时不存在/重复时刻的处理由文档 02 定义。条件监控要有可机器验证的条件、抑制重复通知的状态、冷却时间、到期日和最大执行次数。

项目默认条件监控最快 5 分钟一次，实际不能超过来源限流；这不是钉钉官方限额。默认有效期 30 天，到期提前通知续期，不创建隐形永久任务。

## 10. 线上业务问答：公司 MCP

公司已有 MCP 是外部事实来源（另一个项目的企业 AI 底座），不要求重建代码托管或日志平台。代码、日志的真实工具名、输入 schema、身份透传方法和错误格式由接入阶段发现并登记；本规范中的“代码搜索”“日志查询”均为语义能力名称，不假定公司已有同名端点。

**代码查询、日志查询、数据查询三条路径统一经公司 MCP 执行。** 本项目不直连企业代码库、日志平台或业务数据库，也不内置可绕过 MCP 的 HTTP/SQL 数据适配器。三类查询分别使用独立审核的 MCP 配置（地址、transport、认证、固定工具名与 schema hash）、独立的资源与身份范围；未配置或未审核的工具保持 `UNCONFIGURED`/`UNVERIFIED`，不得以本地假数据冒充真实结果。

一次排障结果至少区分：生产环境与时间段、日志事实、代码静态行为、发布版本是否匹配、相关性与因果性、截断/采样、缺失证据、建议的验证步骤。

如果代码来自主分支而日志来自另一部署版本，必须标注版本未对齐，不输出确定根因。若 MCP 只有共享高权限凭据且不支持按调用人限制资源，必须通过受控代理分资源鉴权，否则仅允许管理员试点，不能全员上线。

## 11. 数据统计与数据部门协作

以“认证指标/查询模板优先”替代“让模型任意写 SQL 访问生产库”。数据部门提供：指标定义、粒度、去重键、时间字段/时区、延迟、维度、可筛选项、可见角色、参数 schema、执行方式、测试输入和预期结果。

模型自主选模板、追问缺失口径、组合结果、生成解释和图表；确定性执行层负责参数校验、模板版本核对、权限范围绑定、查询限额和结果口径验证，实际数据查询经公司 MCP 的数据工具执行。没有认证模板或上游 MCP 未提供数据工具时生成待开发需求并标记 `BLOCKED_EXTERNAL`，不假装已有统计能力。

支持多模板分析，但必须验证粒度一致、分母一致、时间窗一致和数据水位。大数据查询在 MCP 上游的数据服务侧执行；PostgreSQL 是平台状态数据库，不是把公司所有明细集中复制过来，也不作为数据查询的旁路。

默认对外输出聚合结果，明细导出需要独立权限。统计口径、模板版本、执行时间、数据新鲜度、行数及截断状态必须随报告保存。

## 12. 文件、搜索与办公事项

### 12.1 搜索

公网搜索接入真实搜索提供商；企业搜索走已授权 DWS/知识源。两者的查询与结果隔离，公网搜索不能携带内部客户姓名、日志凭据、生产 URL 等敏感内容。搜索不可用时清晰标记，不把模型记忆说成已联网查询。

### 12.2 文件和成果

核心输出格式：Markdown、TXT、CSV、JSON、HTML、XLSX、DOCX、PDF。所有格式由代码生成，不假设模型直接返回合法二进制。XLSX 必须验证公式/单元格；DOCX/PDF 检查文本与页面；HTML 禁止执行任意脚本。PPTX 等可通过认证插件扩展。

输入文件经过类型探测、大小限制、压缩炸弹防护、恶意内容检查和来源授权。嵌入的“忽略规则”“把文件发给某人”等文字只作为资料，不是执行指令。

成果链接走应用鉴权与下载时 ACL 检查。群成员变化后，已发到群里的正文不能追溯抹除；敏感报告默认只发摘要和受保护链接，不把完整明细嵌在卡片或文件附件中。

### 12.3 办公闭环

待办：新建、查询、更新、关闭；日历：查忙闲、候选时间、预览、创建/改期、验证；文档/钉盘：检索、读取、授权内创建/编辑、冲突处理；AI 表格：读取结构、查询、受控写入；审批/报告/纪要：仅对认证能力开放。

“提交审批”与“代表审批人同意”是不同风险，不能混为一个 write 权限。机器人也不能自主打卡、给员工做绩效评分、批量删人或把文件公开分享。

## 13. 管理界面

使用钉钉内 H5 工作台，并提供同源浏览器管理入口。必须包含以下页面：

- 总览：运行状态、待审批、连接异常、队列、费用与失败任务。
- 能力中心：每个能力的可用状态、授权主体、真实验证日期、缺失条件、重新检查。
- 用户与组织：身份映射、部门、角色、授权与离职失效。
- 群管理：群合同、模式、来源覆盖、事务、主动消息预算、暂停。
- 个人中心：人设、记忆、定时任务、个人 DWS 连接、数据删除。
- 任务中心：步骤摘要、证据、审批、取消、失败重试、输出和核验状态。
- 数据模板：版本、指标、参数、权限、测试样例、发布与回滚。
- 审计与运维：敏感操作、策略变更、密钥轮换状态、备份恢复演练。

每个列表、详情和操作后端都重新授权。管理员不能因为拥有控制台就默认查看员工私聊内容；受控审计访问需独立授权、理由和记录。
