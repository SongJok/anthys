# Optional owned DM capture diagnostics

The collector remains offline by default. `--diagnostics` adds sanitized terminal statistics only to an already separately authorized `--live` capture invocation. It does not grant authorization, start another window, extend the existing deadline, enable reconnect, change subscriptions, relax any acceptance filter or add an ACK. Default output and the private metadata contract remain unchanged.

The pinned SDK2.1.5 `connect()` awaits `_connect()`, which resolves on the WebSocket `open` event and sets `connected=true`. The child also requires that flag before READY. SDK `SYSTEM/REGISTERED` is a separate observation; READY alone does not prove registration or continuous availability. `onDownStream`, `onCallback`, `onSystem` and `_connect` observations forward the original arguments/method results unchanged. Only counters and observed lifecycle flags enter diagnostics.

Fixed counters distinguish SDK callback envelopes, exact-topic callbacks and subscribed listener invocations. Single first-rejection counts use fixed enums: inactive, envelope, frame_size, json, forbidden_payload, body_shape, not_private, chatbot_corp, sender_corp, staff, robot, self_robot, nonce_format, nonce_value, time. The original rejection order and exact acceptance set are preserved. Format/value tests keep the exact lowercase 32hex nonce marker, including rejecting whitespace or trailing line endings. Diagnostics contain no body, identity, message ID, URL, nonce or digest.

Diagnostics are opt-in on the private START message and use strict owned IPC schemas. The child publishes bounded snapshots while events happen, before parent force-kill can discard child-only counters. It sends at most128 normal snapshots plus one terminal snapshot; the last normal snapshot marks `truncated` before the cap, and numeric counters saturate at1000000. A synchronous IPC send failure cannot recurse through `finish`; unknown/extra fields, invalid counts or sequence replays are rejected. Parent close confirmation comes from the actual owned ChildProcess close event.

The CLI emits one `DM_CAPTURE_DIAGNOSTICS_V1` JSON line to stderr at termination. `observed=false/snapshot=null` means no valid owned snapshot arrived; it cannot be called zero callbacks. A zero-callback interpretation requires `observed=true`, `snapshot.truncated=false`, and the actual terminal/window context. Counts describe observations through the last received snapshot, not proof that a platform never delivered a packet. With `truncated=true`, counts are bounded/incomplete observations, even if a field is zero. `registeredSeen`, `webSocketOpenSeen` and `socketCloseSeen` mean events were observed; they do not assert the entire window's current state. `readyConnectedFlag` records the child's actual SDK readiness check. `ownedChildClosed` confirms parent-observed process closure; an absent socket close event does not imply a surviving socket after force-kill.
