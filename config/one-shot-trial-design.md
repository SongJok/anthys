# 一次性单聊控制设计（未启用真实试验）

完整 P00–P14 与 ENTERPRISE_DWS 基线继续有效。本入口只提供后续受控试验所需的限制，不代表企业验收通过。未批准具体员工、时长、额度或真实发送；本次只操作 53331 的新增合成记录，不加载真实配置。

1. 每租户最多一条不可删除、不可重新武装的记录（按租户键隔离 RLS，部署仍只允许一个明确主体）。配置指纹、企业、员工、机器人、DM 会话、预算策略指纹、截止时间一经创建不可变。ARMED → BOUND → CLOSED；第一条合格消息在同一事务内绑定 msgId/taskId/runId。相同消息重复 ACK，另一条消息拒绝，不产生控制回执。入口在停止、澄清、记忆、人设分支之前拒绝命令、群聊、附件、非指定主体。
2. 无工具模式：模型的工具数组为空；Gateway 在查找注册工具之前拒绝执行，包括 CORE 和伪造工具。固定内置人设，不读取用户记忆或企业资源。默认完整模式保留。
3. 所有边界使用数据库 clock_timestamp()，在取得相关锁后复核。事务拒绝不能把关闭状态一同回滚：拒绝回滚后独立提交关闭。关闭持久取消任务，抑制待发投递；在途发送保留 UNKNOWN。本地在途请求接收关闭/到期信号；已经发出的远程请求无法撤回。
4. 恢复先检查 DISPATCHING/SENDING/UNKNOWN，再改变 fence、发布或重试。UNKNOWN 永久关闭，不释放不明金额；原预算账本负责恢复与后续实际结算。生成和语义审核共用唯一 task 的 LIFETIME 桶，跨日不重置。配置缺失或变化也不能解除数据库限制。健康租约中的 DISPATCHING/SENDING 会拒绝新进程启动；只有租约失效、已标记 UNKNOWN 或发送租约超时才作为孤儿关闭，不误取消健康进程。
5. 应用启动先核验数据库记录与配置。受限分支跳过 MCP、DWS、附件、卡片等连接初始化，强制回复模式。LIVE_TEST_ENABLED 不参与放行。记录由显式迁移权限操作预置，运行进程不能新建、删除或重新开启。

验证顺序：先落库结构和合成场景，在现有真实路径记录业务断言失败，再实现限制。覆盖错主体/群/附件/命令、并发唯一绑定、CORE/伪造工具、锁等待越过截止、在途取消、模型与发送 UNKNOWN、孤儿恢复、旧 outbox、缺失/变化配置重启、唯一任务跨日累计；保留正常接收与默认模式正例。模拟 provider 只验证本地控制，不记为真实联调。

当前交付进度以对应报告为准。应用预算限制本地预约与派发，不是供应商硬计费上限。

配置入口是 ONE_SHOT_TRIAL_PROFILE_FILE，严格字段由 packages/config/src/one-shot-trial.ts 定义。它仅核对已预置记录，不能武装试验。DM 会话 ID 必须来自已存在、经企业确认的可信会话元信息；没有该 ID 则 BLOCKED_EXTERNAL，不发送额外探针来获取。记录只保存配置/预算指纹和控制元信息，不保存凭据或审批原文。预算策略必须另行提供且与指纹相同；本次没有批准或填写真实额度。

运行入口仍使用原 start:ingress、start:worker、start:notifier；三者先完成配置核验，再启动试验。受限租户的网页和维护进程拒绝启动。未配置试验的其他租户保留默认行为；无作用域启动仅做内容无关的存在性检查并拒绝降级。试验中的任意重启遇到健康在途请求会拒绝新进程，等待其完成或租约过期后再核对，不把启动当作重试授权。

离线验证命令（通过隔离脚本去除企业配置和凭据）：

```sh
node scripts/run-tests.mjs vitest run tests/integration/one-shot-trial.test.ts --maxWorkers=1
node scripts/run-tests.mjs vitest run --coverage --maxWorkers=2
pnpm typecheck
pnpm lint
pnpm build
```

不得把这些命令换成加载真实 .env 的直接测试命令。执行结果、失败记录和对应源码指纹在 reports/checks/one-shot-*.json。任务失败、预算不足或本地中断会关闭本次试验，自动重试不产生第二次机会。完成后的发送状态仍是 APPLIED_UNVERIFIED，不能当作平台回执已核验。

取消监视器每 100ms 核对数据库，并给独立查询连接设置 1000ms 的客户端查询及 PostgreSQL statement 超时。首次读取数据库剩余时间后，用本地单调倒计时独立取消，保守扣除首次查询往返时间；行锁阻塞或网络故障不能延长本地在途请求。数据库不可达时停止本地请求，禁止新的授权派发；持久关闭只能在数据库恢复可写后提交，不能声称离线时已经写入。已有远端请求可能继续执行或计费，后续核对费用仍必需。

最终隔离补强使用新增 064：绑定元信息的表级 RLS 同时限制租户和指定员工；恢复出来的非零队列代次或来源/群续答指针持久关闭试验，在取得新 fence 前拒绝；既有 H5 续答路径也在写入第二个输入前拒绝。061–063 已应用文件保持原样。所有这些均为合成反例验证，不是生产部署记录。
