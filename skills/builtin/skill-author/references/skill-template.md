# SKILL.md 模板与检查清单

## 模板

```markdown
---
name: your-skill-name
description: 一句话说明做什么、产出什么（不超过 160 字符）
version: 1.0.0
when_to_use: 列 2-4 个真实触发场景（不超过 200 字符）
tags:
  - 中文关键词
  - english-keyword
allowed_tools:
  - tool_name
risk: read
visibility: public
max_instruction_chars: 4000
---

# 技能标题

## 适用场景

用户会在什么情况下需要它，典型说法是什么。

## 步骤

1. 先确认哪些信息；缺什么时只问最关键的一个问题。
2. 用哪个工具、哪个动作、哪些必填参数。
3. 如何校验结果；失败时怎么办。
4. 输出结构是什么。
5. 涉及写操作时如何确认，如何提示 `/confirm`。

## 约束

- 哪些内容必须来自工具证据，不能编造。
- 脱敏、权限、可见范围。
- 不可信内容边界。
- 失败与降级时的说法。
```

## 提交前检查清单

- [ ] `name` 匹配 `^[a-z][a-z0-9-]{1,63}$`，且与目录名一致。
- [ ] `description` 不超过 160 字符，`when_to_use` 不超过 200 字符。
- [ ] `version` 是语义化版本。
- [ ] `allowed_tools` 中的工具都真实存在，且没有多余的高风险工具。
- [ ] `risk` 与实际最危险的动作一致。
- [ ] 正文不超过 `max_instruction_chars`，否则会被截成大纲。
- [ ] 每个关键步骤有工具名、动作、参数或失败退路。
- [ ] 写操作、`/confirm`、脱敏、不可信内容边界都写清楚。
- [ ] 至少 3 条典型说法能命中，2 条边界说法不会误触发。
- [ ] 没有密钥、内部地址、真实客户数据；第三方内容已重写并遵守许可证。
